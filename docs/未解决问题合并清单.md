## 一、高严重（H）

### H-01 大文件分段保存后缓存错位，界面回显旧内容（◐ 部分解决）　`(src: H4)`
- **位置**：`EditorViewModel.kt:568`（`savePagedEdit`）、`:418`（`saveAndSwitchEdit`）
- **问题**：两处均用 `preserveUntil = index + 1`，`loadPaged` 的 `filterKeys { k -> k < preserveUntil }` 会**保留被编辑块 `index` 的旧缓存文本**，而重载循环只从 `index+1` 开始——保存后该块永远展示编辑前内容；字节长度变化后其后块边界已平移，`saveAndSwitchEdit` 保留的旧块属**错位缓存**。
- **状态**：写空事故（原 A1）已堵，但分段编辑缓存错位（旧内容回显）未修复，用户可感知"保存了却没变"。
- **建议**：`preserveUntil` 应为 `index`（仅保留编辑块之前的块）。

### H-02 `file://` 随机写非原子，写盘中断致文件永久损坏（◐ 部分解决）　`(src: H5)`
- **位置**：`EditorViewModel.kt:604-655`（`persistFileRandomWrite`）
- **问题**：对原文件就地 `seek+write`，中途进程被杀/断电则半新半旧；变长分支"写新块→写尾部→`setLength`"同样直接作用于原文件，`catch` 仅返回 `false`，无备份可回滚。
- **状态**：写空事故已堵，但就地写非原子仍是数据损坏风险。
- **建议**：为脏块之后的原始内容保留可回滚副本，或整体 `temp + rename` 原子写。

### H-03 自动保存与手动保存竞态致内容回退（● 未解决）　`(src: X-H1)`
- **位置**：`EditorViewModel.kt:925`（`performAutoSave` catch）、`:933`（`scheduleAutoSave` 无兜底 launch）、`saveAndExit` 并发路径
- **问题**：自动保存（停输 3 秒触发）与手动/退出保存均未加互斥；自动保存失败被静默吞掉（`:925` `catch (_: Exception)`），用户误以为已保存；若自动保存协程在手动保存写盘中途读旧 `currentContent`，可能把旧内容写回覆盖新结果，造成"保存后内容回退"。
- **建议**：保存路径加单飞锁（Mutex）或 in-flight 标记；自动保存跳过正在进行的人工保存，且失败须提示。

### H-04 非 Markdown 文件被误套列表续行格式化（● 未解决）　`(src: X-H2)`
- **位置**：`AutoTextFormatter.kt` / 编辑器格式化分发
- **问题**：列表续行/缩进逻辑按"是否可格式化格式"分发，但非 Markdown 文本（`.txt/.csv/.json`）也被套用 Markdown 列表续行规则，普通文本回车被错误追加 `- `/`1. ` 或缩进，污染非 Markdown 内容。
- **建议**：格式化仅对 Markdown 启用，非 Markdown 走纯文本分支。

## 二、中严重（M）

### M-01 长文档渲染在主线程（卡顿/ANR）　`(src: A4)`
- **位置**：`MarkdownPreview.kt:71-100`（主线程预处理 + `MarkdownParser.parse`）、`:266,294`（`markwon.setMarkdown` 主线程）；`EditorScreen.kt:511`
- **问题**：预处理（多个正则）+ 解析 + `setMarkdown` 全在主线程，未迁 `Dispatchers.Default`。大文档易掉帧甚至 ANR。

### M-02 `compileSdk=35` + AGP 8.4 用 suppress 掩盖　`(src: A5)`
- **位置**：`gradle.properties:17`、`app/build.gradle.kts:20`、`gradle/libs.versions.toml:4`
- **问题**：AGP 8.4 官方仅支持到 compileSdk 34，用 `suppressUnsupportedCompileSdk` 抑制报错，属"编译期被忽略、运行/资源期可能异常"隐患。
- **建议**：升级 AGP 到原生支持 API 35 的版本后移除 suppress。

### M-03 HtmlPlugin 渲染不可信原始 HTML（远程 `<img>`）　`(src: A6)`
- **位置**：`MarkwonConfig.kt:174`
- **问题**：`preprocessImagePaths` 只处理 `![](...)`，对 HTML 内联 `<img src="http(s)://...">` 全放行，经 Coil 直接加载。**当前因 `AndroidManifest` 未声明 `INTERNET` 权限，远程图片实际无法加载（有效缓解）**；一旦加 `INTERNET` 即构成隐私泄露/追踪通道，绕过 §4.1 图片安全设计。
- **建议**：评估 HtmlPlugin 白名单或移除原始 HTML 渲染。

### M-04 声明 `MANAGE_EXTERNAL_STORAGE` 违反最小权限　`(src: A7)`
- **位置**：`AndroidManifest.xml:21`
- **问题**：声明了该权限（`tools:ignore="ScopedStorage"`，无 `maxSdkVersion`），代码未实际申请，但声明本身即隐患，**一旦误调用即授予全盘访问**，远超 §4.6 限定的 Documents/Download 范围。
- **建议**：移除该声明（或加 `maxSdkVersion` 约束 + 明确不申请）。

### M-05 `textFieldValue` 双向同步 + `LaunchedEffect` 整串为 key　`(src: A10)`
- **位置**：`EditorScreen.kt:158`、`:164-195`、`447-489`
- **问题**：`BasicTextField.value` 既本地持有又经 `LaunchedEffect(currentContent)` 回灌，靠 `isInternalUpdate` 防回环；key 是**整个 `currentContent` 字符串**，每次按键 O(n) 全量比较，大文件有卡顿/重组隐患。
- **建议**：用单向状态流（ViewModel 为唯一真源）替代双向同步。

### M-06 `allowBackup="true"` 可被 adb 提取　`(src: A13)`
- **位置**：`AndroidManifest.xml:33`（未定义 `backupRules`）
- **问题**：`adb backup` 后可提取应用私有数据（隐藏 URI 集合、阅读位置等，敏感度低）。建议设 `false` 或配置 `backupRules`。

### M-07 预处理管线（含磁盘 I/O）在主线程组合期同步执行　`(src: M1)`
- **位置**：`MarkdownPreview.kt:71-76`（每张相对图片一次 `File.exists()`）；`EditorScreen.kt:103-109`（`resolveBaseDir` 查 MediaStore）
- **问题**：图片多的文档首次组合即数千次 stat 系统调用，与全量渲染叠加是 ANR 直接成因。
- **建议**：预处理下沉 IO 调度器并缓存结果。

### M-08 HtmlPlugin 与 `<sub>/<sup>` 结论矛盾，且全量放行原始 HTML　`(src: M3)`
- **位置**：`MarkwonConfig.kt:174`；`SubscriptPlugin.kt:66` / `SuperscriptPlugin.kt:66`；`AGENTS.md §5.1`
- **问题**：AGENTS.md 写"HtmlPlugin 不支持 `<sub>/<sup>`，用 Unicode 占位替代"，但实现直接输出 `<sub>/<sup>` 依赖 HtmlPlugin 渲染——二者必有一处错。同时原始 HTML 全量放行（见 M-03）。
- **建议**：真机验证上下标后修正文档或实现。

### M-09 代码块深色背景未统一为 `#2D2D2D`　`(src: M5)`
- **位置**：`CodeBlockCard.kt:79`（卡片底 `#1E1E1E`）；`MarkwonConfig.kt:119`（TRANSPARENT）、`:146`（完整版 `#2D2D2D`）
- **问题**：围栏代码块代码区透出卡片底 `#1E1E1E`，而文本段内缩进代码块为 `#2D2D2D`——同屏两种背景不一致。
- **建议**：统一卡片底色，或修正文档描述。

### M-10 上下标 LaTeX 区间跳过的两类误判　`(src: M6)`
- **位置**：`SubscriptPlugin.kt:119-136` / `SuperscriptPlugin.kt:119-136`
- **问题**：(a) 单 `$` 向后配对不限换行，跨多行整段被当 LaTeX 区间跳过，其中合法 `~x~`/`^x^` 失效；(b) 不识别转义 `\$`。两插件该函数完全重复约 20 行。
- **建议**：单 `$` 配对限制同行 + 识别 `\$`；提取公共函数。

### M-11 TocParser 与 MarkdownParser 围栏判定不一致　`(src: M7)`
- **位置**：`TocParser.kt:43-48`（trim 后 `startsWith("```")`）vs `MarkdownParser.kt:22`（行首锚定）
- **问题**：缩进围栏（≤3 空格）TOC 排除其中标题、预览却不按代码块切分——同一文档大纲与预览认定不一致；双方都不支持 `~~~` 围栏；`TocParser.kt:55` headingRegex 在循环内逐行 `new Regex`。
- **建议**：统一围栏判定逻辑并提取共用；正则预编译。

### M-12 `buildMarkwon` 任一插件异常导致全部插件静默丢失　`(src: M9)`
- **位置**：`MarkwonConfig.kt:138-139, 223-226`
- **问题**：try-catch 包裹整个 11 插件装配，任一插件异常回退裸 Markwon——表格/图片/上下标/任务列表全部消失，catch 块为空无日志。
- **建议**：逐级降级 + 至少 `Log.e`。

### M-13 Markwon 单例缓存长期持有 Activity Context　`(src: M10)`
- **位置**：`MarkwonConfig.kt:50-57, 63-73`；调用点 `MarkdownPreview.kt:103-109`
- **问题**：`object MarkwonConfig` 进程级存活，缓存键仅 `isDarkTheme`，Activity 销毁后旧实例仍被单例引用——Activity 泄漏风险。
- **建议**：构建时用 `context.applicationContext`。

### M-14 MainActivity 不处理 `ACTION_SEND_MULTIPLE`　`(src: M11)`
- **位置**：`MainActivity.kt:106-133`；`AndroidManifest.xml:195-208`
- **问题**：外部多文件分享落入 `else -> null`，manifest 也未声明 `SEND_MULTIPLE`；应用自身支持多选外发，接收侧不对称。
- **建议**：确认是否需要接收多文件分享；需要则补过滤器 + 处理逻辑。

### M-15 pathPattern 与文档不符、深度不自洽、大小写敏感　`(src: M13)`
- **位置**：`AndroidManifest.xml:120-151, 162-189`
- **问题**：实际每过滤器 **28 条**（16+8+4）共 56 条，与文档"31 个"对不上；`.conf/.env/.properties/.csv/.log/.bash/.zsh/.dockerfile` 仅一级覆盖，`a.b.csv` 二级路径无 MIME 时匹配不到；pathPattern **大小写敏感**，`.TOML` 不命中；`octet-stream` 无路径限定，`.apk/.zip` 也出现在打开方式列表。
- **建议**：修正文档计数；补齐深度与大小写变体；考虑收窄 octet-stream。

### M-16 主线程阻塞式 `ContentResolver` 查询 + 协程缺异常兜底　`(src: X-M1)`
- **位置**：`EditorViewModel.kt:165,172`（经 `LaunchedEffect` 跑 `Dispatchers.Main` 调用 `StorageRepository.kt:1079/347` 同步 CP 查询）；`FileListViewModel.kt:482`；`EditorViewModel.kt:989-1007`（`insertImage` launch 无 try/catch）
- **问题**：打开/导入时主线程做阻塞式 CP 查询（jank/StrictMode）；个别 `launch` 无 `CoroutineExceptionHandler`，异常未兜底。

### M-17 URI scheme 分发重复，无统一入口　`(src: X-M2)`
- **位置**：`StorageRepository.kt:322/375/393/438/454/711/774` + `EditorViewModel.kt:626`
- **问题**：`file://`/`content://` 分支在 ≥7 个方法内各自实现，无中央 URI 规范化/分发器；新增存储后端（如 SAF tree URI）易漏改一处。
- **建议**：抽 `UriDispatcher` 统一归一化与分发。

### M-18 批量删除多 URI 授权仅用首个 IntentSender　`(src: X-M3)`
- **位置**：`StorageRepository.kt:738-739`；`FileListViewModel.kt:275-281`
- **问题**：`consentExceptions.firstOrNull()?.let { throw it }` 在返回前抛出，多文件需授权时**只有第一个**能进入授权重试，其余静默失败；已成功物理删除的 URI 集合在异常时被丢弃，ViewModel catch 后直接 return，内存列表不更新（与 H-03 同源）。
- **建议**：异常携带已成功集合，先移除已删项再触发授权。

### M-19 主保存路径非原子写　`(src: X-M4)`
- **位置**：`EditorViewModel.kt`（`saveContent` 常规保存主路径）
- **问题**：`saveContent` 直接覆盖原文件，无 `temp + rename`，写中途崩溃留半文件（与 H-02 同根）。

### M-20 Coil 外部图片按原始分辨率解码，多图易 OOM　`(src: X-M5)`
- **位置**：`MarkwonConfig.kt:162`（`CoilImagesPlugin.create(context)` 默认 CoilStore，请求未设 `.size()`）
- **问题**：外部引用图按原图全分辨率解码（4000×3000 ARGB_8888 ≈ 48MB/张），多图 .md 瞬时数百 MB，存在 OOM 风险（应用自身插入图已限 2048px，外部引用无限制）。
- **建议**：为外部图设 `size`/采样上限。

### M-21 Markdown 图片相对路径未做 canonical 越界校验　`(src: X-M6)`
- **位置**：`MarkwonConfig.kt`（`preprocessImagePaths` 拼接相对路径）
- **问题**：相对路径拼接未规范化，`../` 可越出 `.md` 同级 `images/` 读取应用私有文件，构成信息泄露面（与 §4.1 图片安全冲突）。
- **建议**：拼接后校验 canonical 路径仍在 `.md` 目录下。

### M-22 `requestLegacyExternalStorage` 在 API30+ 死属性 + prism `includeAll` 冗余打包　`(src: X-M7)`
- **位置**：`AndroidManifest.xml:39`；`Prism4jBundle.kt:15-17`
- **问题**：该属性 targetSdk=35 下对 API30+ 静默失效，造成"支持旧存储"错觉；prism 打包全部语法约 50 种，增大包体。
- **建议**：移除死属性；按需裁剪 prism 语法包。

### M-23 仅单元测试、零 instrumentation 测试　`(src: X-M8)`
- **位置**：`app/src/androidTest` 为空；仅 `app/src/test` JVM 单测
- **问题**：核心保存/分页编辑回写/权限授权重试无 UI 测试，回归只能靠手测。
- **建议**：补关键流程 Espresso/Compose UI 测试。

### M-24 中文字符串大量硬编码于 Compose/Kotlin　`(src: X-M9)`
- **位置**：`BottomActionBar.kt:59,73,87,104` 等
- **问题**：`strings.xml` 已有资源未复用，国际化与复用受阻（与 L-73 同源）。

### M-25 读取失败被静默吞掉、伪装成空内容　`(src: X-M10)`
- **位置**：`StorageRepository.kt:296-306`（`readFileContent` catch 返回 `null`）→ `EditorViewModel.kt:216`（`readContent(...) ?: ""`）
- **问题**：真实读取错误（文件被锁/损坏）得到空编辑器且无 `errorMessage`，用户不知读取失败。
- **建议**：读取失败抛出/展示错误状态，不伪装为空。
