# MarkFlow 代码全面审查报告

> 审查范围：`app/src/main` 全部源码（约 1.05 万行 Kotlin）+ AndroidManifest + 构建配置 + ProGuard 规则，逐文件通读，并与 README.md / AGENTS.md 的设计约束逐条交叉核对。
> 审查日期：2026-09-03。仅审查，未修改任何代码。
> 严重级别：**高** = 数据损坏/崩溃/功能性缺陷；**中** = 行为错误/一致性问题/明显隐患；**低** = 边界问题/死代码/文档漂移。

---

## 一、高严重级问题（7 项）

### H1. 大 .md（>1MB）预览无任何降级保护，必现 ANR/OOM
- 位置：`ui/components/MarkdownPreview.kt:136-178`；调用点 `ui/screens/editor/EditorScreen.kt:511-518`
- 问题：`MarkdownPreview` 为 `Column + verticalScroll` **全量渲染**，无任何大小阈值判断（分页保护仅对 .txt 生效）。AGENTS.md §10.3 已记录该方案"已拍板未实现"，2.38MB/53607 行压测文件已实测崩溃。
- 建议：实现已拍板的方案 2——大 .md 预览降级为分页只读纯文本（复用 PagedTextSource），编辑保留全文但禁用语法高亮。

### H2. 编辑态语法高亮无 debounce、无后台线程，主线程每键全量跑 11 个正则
- 位置：`ui/components/MarkdownSyntaxHighlighter.kt:129-156`；启用点 `EditorScreen.kt:1066-1082`
- 问题：`filter()` 是 VisualTransformation 的同步回调，主线程对每次文本变化全量执行 11 个 `findAll`。**AGENTS.md §4.6 声称"后台线程 + 80ms debounce"，代码中不存在**——文档与实现严重不符。大文档编辑时输入卡顿。
- 建议：高亮计算下沉到后台线程 + 80ms debounce，结果回主线程应用。

### H3. UTF-16 大文件分页必然错位乱码
- 位置：`util/PagedTextSource.kt:218-220, 231-239`
- 问题：块边界按**单字节** `0x0A` 查找换行。UTF-16LE 的 `\n` 是 `0A 00`，切在 0A 之后下一块从奇数字节界开始解码，**整块全部错位**；UTF-16BE 同理。EncodingDetector 明确支持 UTF-16 BOM 探测，PagedTextSource 消费其结果，两条链路组合即触发。单行超 200KB 强制截断同样会把多字节字符从中间切开。
- 建议：块边界按编码单元对齐（UTF-16 取偶偏移、UTF-8 回扫完整字符）。

### H4. 大文件分段保存后缓存保留被编辑块本身，界面回显旧内容（疑似保存失效）
- 位置：`ui/screens/editor/EditorViewModel.kt:568`（`savePagedEdit`）、`:418`（`saveAndSwitchEdit`）
- 问题：两处均用 `preserveUntil = index + 1`，`loadPaged` 的 `filterKeys { k -> k < preserveUntil }` 会**保留被编辑块 index 的旧缓存文本**，而重载循环只从 `index+1` 开始——保存后该块永远展示编辑前内容。且编辑块字节长度变化后其后块边界已平移，`saveAndSwitchEdit` 保留的旧块属于**错位缓存**。
- 建议：`preserveUntil` 应为 `index`（仅保留编辑块之前的块）。

### H5. file:// 随机写非原子，写盘中断可致文件永久损坏
- 位置：`ui/screens/editor/EditorViewModel.kt:604-655`（`persistFileRandomWrite`）
- 问题：对原文件就地 seek+write，write 中途进程被杀/断电则文件处于半新半旧状态；变长分支"写新块→写尾部→setLength"同样直接作用于原文件，catch 仅返回 false，无备份可回滚。
- 建议：至少为脏块之后的原始内容保留可回滚副本，或整体 temp+rename 原子写。

### H6. 批量删除遇授权异常时丢失已删结果，UI 与磁盘状态不一致
- 位置：`data/repository/StorageRepository.kt:738-739`；`ui/screens/filelist/FileListViewModel.kt:275-281`
- 问题：`consentExceptions.firstOrNull()?.let { throw it }` 在返回前抛出，已成功物理删除的 URI 集合被丢弃；ViewModel catch 后直接 return，内存列表不更新——已删文件仍显示在列表中，且未执行 unhideFiles 清理。多个文件需授权时**只有第一个**能进入授权重试，其余静默失败无任何提示。
- 建议：异常携带已成功集合，ViewModel 先移除已删项再触发授权流程。

### H7. MediaStore 扫描遇脏数据行（DISPLAY_NAME 为 null）导致整次扫描中断
- 位置：`data/repository/StorageRepository.kt:187`
- 问题：`getString(nameColIdx)` 平台类型直接赋非空引用，单行 null 即抛 NPE，被外层 `catch (e: Exception)` 吞掉——**已解析的行保留、后续行全部丢失**；若首行即 null 则整个列表为空。极端 ROM 上一行脏数据即可让文件列表变空或截断。
- 建议：行级 try-catch 跳过坏行，或对 null 文件名跳过该行。

## 二、中严重级问题（14 项）

### M1. 预处理管线（含磁盘 I/O）在主线程组合期间同步执行
- 位置：`MarkdownPreview.kt:71-76`（每张相对路径图片一次 `File.exists()`）；`EditorScreen.kt:103-109`（`resolveBaseDir` 查 MediaStore）
- 问题：图片多的文档首次组合即产生数千次 stat 系统调用，与 H1 叠加是大文件 ANR 直接成因。
- 建议：预处理下沉 IO 调度器，结果缓存。

### M2. LaTeX/图片预处理不排除代码块区间，篡改代码示例内容
- 位置：`util/MarkwonConfig.kt:242-258, 377-415`
- 问题：预处理在原始全文做正则替换，不排除围栏代码块与行内代码。代码示例中的 `$x^2$` 会被改写成 `$$x^2$$`；代码中的 `![a](b.png)` 会被路径解析、文件不存在时替换为 `图片a` 纯文本——**代码内容被静默篡改**，技术文档场景必现。
- 建议：预处理前先按围栏切分，仅处理文本段。

### M3. HtmlPlugin 与 AGENTS.md 的 `<sub>/<sup>` 结论矛盾，且全量放行原始 HTML
- 位置：`MarkwonConfig.kt:174`；`SubscriptPlugin.kt:66` / `SuperscriptPlugin.kt:66`；`AGENTS.md:103`
- 问题：AGENTS.md 陷阱清单写"HtmlPlugin 不支持 `<sub>/<sup>`，用 Unicode 占位替代"，但当前实现直接输出 `<sub>/<sup>` 依赖 HtmlPlugin 渲染——二者必有一处错误（要么上下标静默失效、要么文档过期）。同时原始 HTML 全量放行存在注入渲染面，既有评审（docs/code_review_2026-09-03.md A6）已建议移除或过滤。
- 建议：真机验证上下标渲染后修正文档或实现；评估 HtmlPlugin 白名单。

### M4. 预览搜索高亮的"当前匹配"定位错误，且整体是死路径
- 位置：`MarkdownPreview.kt:365-373, 478-506`；调用点 `EditorScreen.kt:512-518`
- 问题：(a) 段内第一个匹配被当作全局当前匹配涂橙色，全局当前匹配在该段内为第 N 个时标错位置；(b) EditorScreen 调用 MarkdownPreview **未传 searchQuery/currentSearchIndex**，整套预览搜索高亮当前是死代码——遗漏接线或应删除。
- 建议：厘清意图后接线（全局偏移换算段内偏移）或移除。

### M5. 代码块深色背景并未统一为 #2D2D2D
- 位置：`ui/components/CodeBlockCard.kt:79`（卡片底 `#1E1E1E`）；`MarkwonConfig.kt:119`（代码区背景 TRANSPARENT）、`:146`（完整版 `#2D2D2D`）
- 问题：约束要求"代码块深色背景统一 #2D2D2D"。实际围栏代码块代码区透出卡片底 `#1E1E1E`（仅顶栏 #2D2D2D），而文本段内缩进代码块为 #2D2D2D——同屏两种代码块背景不一致。
- 建议：统一卡片底色或修正文档描述。

### M6. 上下标 LaTeX 区间跳过的两类误判
- 位置：`util/SubscriptPlugin.kt:119-136` / `SuperscriptPlugin.kt:119-136`
- 问题：(a) 单 `$` 向后找配对时不限换行，`"价格 $100 …（多行）… 再付 $50"` 中间整段被当作 LaTeX 区间跳过，其中合法的 `~x~`/`^x^` 失效；(b) 不识别转义 `\$`。另：两插件该函数完全重复约 20 行，未提取公共工具。
- 建议：单 `$` 配对限制同行 + 识别 `\$`；提取公共函数。

### M7. TocParser 与 MarkdownParser 围栏判定不一致
- 位置：`util/TocParser.kt:43-48`（trim 后 `startsWith("```")`）vs `util/MarkdownParser.kt:22`（行首锚定，不允许前导空白）
- 问题：缩进围栏（CommonMark 允许 ≤3 空格）：TOC 排除其中标题、预览却不按代码块切分——同一份文档大纲与预览认定不一致；双方都不支持 `~~~` 围栏。另 `TocParser.kt:55` 的 headingRegex 在循环内逐行 new Regex。
- 建议：统一围栏判定逻辑并提取共用；正则预编译。

### M8. 反射路径在 R8 下静默失效
- 位置：`MarkwonConfig.kt:588-595`（反射 `isBlock()`）；`MarkdownPreview.kt:404-408`（反射 `TableRowSpan.cells`）
- 问题：两处反射均无代码内 keep 佐证，release 混淆后异常被 catch 吞掉——公式对齐修复静默禁用、表格复制退化为纯文本，无日志无提示。
- 建议：确认 proguard 覆盖并在 catch 中 Log.e。

### M9. buildMarkwon 任一插件异常导致全部插件静默丢失
- 位置：`MarkwonConfig.kt:138-139, 223-226`
- 问题：try-catch 包裹整个 11 插件装配，任一插件异常回退裸 Markwon——表格、图片、上下标、任务列表全部消失，且 catch 块为空无日志。
- 建议：逐级降级 + 至少 Log.e。

### M10. Markwon 单例缓存长期持有 Activity Context
- 位置：`MarkwonConfig.kt:50-57, 63-73`；调用点 `MarkdownPreview.kt:103-109`（传 `LocalContext.current`）
- 问题：`object MarkwonConfig` 进程级存活，缓存键仅 isDarkTheme，Activity 销毁后旧实例仍被单例引用——Activity 泄漏风险。
- 建议：构建时使用 `context.applicationContext`。

### M11. MainActivity 不处理 ACTION_SEND_MULTIPLE
- 位置：`MainActivity.kt:106-133`；`AndroidManifest.xml:195-208`
- 问题：外部应用向 MarkFlow 多文件分享落入 `else -> null`，manifest 也未声明 SEND_MULTIPLE。应用自身支持多选外发分享，接收侧却不对称。
- 建议：确认是否需要接收多文件分享；需要则补过滤器 + 处理逻辑。

### M12. 导入复制中断残留残缺文件 + 同名文件静默覆盖
- 位置：`MainActivity.kt:166-170`
- 问题：`copyContentUriToLocal` 流复制中途异常时残缺文件留在 imported/（仅 Log 不删除），之后被扫出显示为正常文件；净化后同名文件直接覆盖，两个不同来源同名文件互相踩踏。
- 建议：复制到临时文件完成后 rename；同名时追加序号。

### M13. pathPattern 与文档"31 个"不符，深度覆盖不自洽，大小写敏感
- 位置：`AndroidManifest.xml:120-151, 162-189`；对照 `AGENTS.md:80`
- 问题：实际每个过滤器 **28 条**（16+8+4），共 56 条，与文档"31 个"对不上；`.conf/.env/.properties/.csv/.log/.bash/.zsh/.dockerfile` 只有一级路径覆盖，`a.b.csv` 类二级路径无 MIME 时匹配不到；pathPattern **大小写敏感**，`.TOML` 大写后缀不命中。另 octet-stream 无路径限定，.apk/.zip 等二进制的打开方式列表也会出现 MarkFlow。
- 建议：修正文档计数；补齐深度与大小写变体；考虑收窄 octet-stream。

### M14. 签名缺失的 error() 在 Gradle 配置期爆炸，波及所有任务
- 位置：`app/build.gradle.kts:45-61`
- 问题：`error(...)` 在 `buildTypes.release{}` 配置块内执行，配置阶段即求值——缺 `~/.markflow/keystore.properties` 时 `assembleDebug`、IDE sync、`./gradlew tasks` 全部失败，超出文档"仅 Release 构建失败"的语义。且 configuration-cache 开启时修改 keystore.properties 不会使缓存失效，可能用过期签名配置。
- 建议：改为执行期校验（`tasks.withType<PackageRelease> { doFirst { … } }`）。
