## 二、真机/模拟器验证场景

### 场景 1：长 .md 文件高亮自动显示（X-H3）

**测试文件**：`docs/测试文档/第2章_笔记(1).md`（26678 字符，约 960 span）

| 步骤 | 预期结果 |
|------|---------|
| 从文件列表点击打开该文件，进入编辑模式 | **立即显示高亮**（标题蓝色粗体、`**加粗**` 粗体、`` `代码` `` 红色），无需长按 |
| 不做任何操作，直接上下滑动 | 滑动流畅，无明显掉帧 |
| 长按选择一段文本 | 选区正常，不回弹顶部 |
| 编辑输入文字 | 高亮实时跟随，输入流畅 |

**修复前表现**：打开无高亮/无加粗，长按后才出现，出现后滑动十分卡顿。

### 场景 2：特殊字符文件名打开（X-H4）

**测试文件**：`docs/测试文档/# C++知识点（母版）.md`（含 `#` 和 `++`）

| 步骤 | 预期结果 |
|------|---------|
| 从文件列表点击打开该文件 | **正常显示内容**，非空白 |
| 标题栏显示文件名 | 显示 `# C++知识点（母版）`（非乱码、非编码态 `%23%20`） |
| 进入编辑模式 | 内容可编辑，高亮正常 |

**修复前表现**：打开一片空白（文件名中 `++` 被 URLDecoder 变成空格，文件找不到）。

**验证原理**：URI 现通过 `savedStateHandle` 传递（字符串原样往返），不经 Navigation 路由编解码，`#`/`+`/`%`/空格/中文均安全。

### 场景 3：导入文件不产生重复 .txt（X-H5）

| 步骤 | 预期结果 |
|------|---------|
| 文件列表顶栏点击"打开文件" | 系统文件选择器弹出 |
| 选中手机中的 `Main.java`（或其他代码文件） | 导入成功，文件列表出现 `Main.java` |
| 检查文件列表 | **只有 `Main.java`，不出现 `Main.java.txt`** |
| 打开该文件 | 内容正确，语法高亮正常（`.java` 走代码高亮） |

**修复前表现**：导入 `Main.java` 后出现 `Main.java` 和 `Main.java.txt` 两个文件。

**验证原理**：`importFile` 改用 `inferMimeType(fileName)` 按扩展名推断 MIME（`.java`→`text/x-java`），MIME 与扩展名匹配，Android 11+ MediaStore 不再自动追加规范后缀。

### 场景 4：长 .md 滑动流畅度优化

**测试文件**：`第2章_笔记(1).md`（26678 字符）

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 高亮 span 数 | ~961 | ~737（去掉列表/引用/分隔线 + 基础色） |
| 打开首次高亮 | 不显示 | 立即显示 |
| 滑动流畅度 | 十分卡顿 | 有改善（"有些卡顿"→更流畅） |
| TransformedText 实例 | 每次新建（触发 relayout） | 缓存复用（跳过 relayout） |

> 注：26K 字符 + 700 span 的 StaticLayout 渲染有固有成本。如果仍感觉轻微顿挫，
> 那是文本量大的固有渲染开销，非 bug。真正的大文档（>1MB）走分页只读，不进此路径。

## 三、代码变更核对

| 文件 | 关键改动 | 检查方法 |
|------|---------|---------|
| `EditorScreen.kt:1096` | `val highlightVersion by markdownHighlighter.highlightVersion`（by 委托） | 搜 `highlightVersion` 确认是 `by` 不是 `=` |
| `MarkdownSyntaxHighlighter.kt` | `transformedText()` 缓存 + 长文档降级高亮 | 搜 `ttCacheValue` / `REDUCED_HIGHLIGHT_THRESHOLD` |
| `Screen.kt` | `Editor.route = "editor"`（无参数）+ `EDITOR_FILE_URI_KEY` | 确认无 `createRoute` 方法 |
| `NavGraph.kt` | `savedStateHandle` 传 URI | 确认无 `URLDecoder` |
| `StorageRepository.kt` | `importFile` 用 `inferMimeType` + `getFileName` 加 `Uri.decode` | 搜 `inferMimeType(fileName)` |
